# 이클립스 공동 필드보스 타이머

접속한 모든 사용자가 같은 보스 시간과 리젠 주기를 보고 수정하는 웹 앱입니다. GitHub Pages는 화면을 제공하고, Supabase의 PostgreSQL과 Realtime이 공동 상태를 저장하고 전달합니다.

**Supabase 프로젝트 xywqclfppwsiiydlniba의 연결 설정과 SQL 적용을 확인했습니다.** 실제 서버에서 두 독립 클라이언트의 Realtime 구독, 동일한 보스 6개 조회, 기존 값을 유지하는 수정 요청이 성공했습니다. GitHub Pages 공개 배포는 별도로 완료해야 합니다.

대상 저장소: https://github.com/gameicom/EclipseSetup

## 1. 공용 데이터베이스 준비

현재 프로젝트의 연결 정보는 **dist/shared-config.js**에 반영되어 있습니다. 아래 절차는 다른 Supabase 프로젝트로 옮기거나 데이터베이스를 새로 준비할 때 사용합니다.

1. https://supabase.com/dashboard 에 로그인하고 프로젝트를 준비합니다.
2. SQL Editor에서 이 저장소의 **supabase/setup.sql** 전체를 실행합니다.
3. 프로젝트의 **Project URL**과 브라우저용 **Publishable key**를 확인합니다. 이전 프로젝트의 anon 키도 지원합니다.
4. **dist/shared-config.js**의 두 값을 채웁니다.

~~~js
export const sharedConfig = {
  supabaseUrl: 'https://프로젝트주소.supabase.co',
  supabasePublishableKey: 'sb_publishable_공개키'
};
~~~

위 두 값은 웹에서 사용하도록 공개되는 값입니다. 비밀 키나 service_role 키는 사용하지 않습니다. 실제 접근 범위는 데이터베이스의 RLS와 함수 권한으로 제한합니다.

SQL은 보스 6개를 담은 한 행을 만들고 Realtime publication에 등록합니다. 이미 만들어진 타이머가 있으면 다시 실행해도 현재 시간을 초기화하지 않습니다. 모든 방문자는 조회와 지정된 수정 함수를 실행할 수 있고, 테이블을 직접 삭제하거나 임의의 행을 추가할 수는 없습니다.

## 2. 로컬 확인

Node.js 22 이상에서 프로젝트 폴더를 열고 실행합니다.

~~~sh
npm ci
npm test
npm run verify:deploy
npm start
~~~

http://127.0.0.1:4173 에 접속합니다. start-web.cmd를 더블클릭해도 실행할 수 있습니다. 서버 연결 설정이 되어 있으면 로컬 주소에서도 같은 Supabase 공동 타이머에 접속합니다.

화면에 **실시간 연결**이 표시되어야 수정할 수 있습니다. 두 브라우저 또는 두 기기에서 열어 한쪽의 보스 시간을 바꾸면 다른 쪽에도 반영됩니다.

## 3. GitHub Pages 배포

1. 이 프로젝트 폴더 안의 파일을 gameicom/EclipseSetup 저장소 루트에 업로드합니다. dist와 .github가 저장소 바로 아래에 있어야 합니다. ZIP 파일 자체를 올리는 것이 아니라 압축을 풀어 내용을 올립니다.
2. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
3. **Actions → Publish boss timer to GitHub Pages → Run workflow**를 실행합니다.
4. 성공 결과에 표시되는 공개 주소를 공유합니다. 예상 주소는 https://gameicom.github.io/EclipseSetup/ 입니다. 실제 배포 성공 전에는 접속 가능한 주소로 간주하지 않습니다.

main 브랜치의 관련 파일을 변경하면 자동으로 다시 배포됩니다. 배포 과정에서 테스트와 공용 데이터베이스 조회를 확인하므로, 서버 연결 값이 비어 있거나 SQL 설정이 빠진 상태는 게시되지 않습니다. 브라우저에서 각 사용자에게 Supabase 로그인은 요구하지 않습니다.

## 공동 수정 동작

- 보스 기준 시각과 리젠 간격을 공동 서버에 저장합니다.
- 서로 다른 보스를 동시에 수정하면 양쪽 변경을 합칩니다.
- 같은 보스를 이전 상태에서 동시에 수정하면 나중 요청은 충돌 메시지를 표시합니다. 최신 시간을 확인하고 다시 설정합니다.
- 전체 초기화는 모든 접속자에게 적용되며, 서버의 한국시간을 사용합니다.
- 되돌리기는 내가 마지막으로 초기화/불러오기한 보스만 복원합니다. 다른 사람이 그 보스를 다시 수정하면 이전 작업으로 덮어쓰지 않습니다.
- 설정 불러오기는 파일의 6개 보스 시간을 모두에게 적용합니다.
- 알림음과 정렬은 각 기기의 개인 선택입니다. 알림음 켜기/끄기로 다른 사람의 소리 설정을 바꾸지 않습니다.
- 연결이 끊기면 마지막으로 읽은 시간을 표시하고 수정을 막습니다. 다시 연결되면 서버의 최신 시간을 받습니다. 오프라인 변경을 나중에 몰아서 덮어쓰지 않습니다.
- 서버 시간을 주기적으로 확인해 기기 시계 차이를 보정합니다.
- 1시간마다 상태를 다시 읽어 유실된 이벤트와 기기 시계 오차를 보완합니다. 정상 연결 중 다른 사용자의 변경은 Supabase Realtime으로 즉시 받습니다. 처음 접속하거나 재연결할 때는 바로 조회하며, 탭 전환은 화면의 남은 시간만 다시 계산합니다. 정기 조회는 연결 하나당 시간당 1회입니다.

## 기본 보스와 알림

Lv.40 / 50 / 60 / 70 / 75 / 80의 기본 주기는 8 / 8 / 10 / 12 / 12 / 15시간입니다. 최초 기준은 2026-10-22의 18:02 / 18:04 / 14:03 / 18:05 / 18:15 / 00:18 (KST)입니다. 이 PC의 저장 설정을 반영한 값입니다.

리젠은 기준 시각에서 자동 반복되며, 5분 이내 리젠을 강조합니다. 브라우저 절전/백그라운드 제한으로 소리 알림은 늦거나 생략될 수 있습니다. 새 탭에서는 소리 테스트로 오디오를 활성화합니다.

Windows 설정 파일은 %LOCALAPPDATA%\EclipseBossTimer\settings.json 에 있습니다. 불러오기 전에 기존 공동 시간을 덮어쓴다는 확인 화면을 표시합니다.

## 검증과 한계

npm test는 기본 시간 계산과 PostgreSQL 엔진(PGlite)에서 실제 SQL을 실행하는 공동 수정 검증을 포함합니다. 독립 클라이언트 두 개, 같은/다른 보스의 동시 수정, 되돌리기, 끊김/재연결, 서버 시간 보정, 유효하지 않은 입력과 권한을 검사합니다. 테스트의 이벤트 전달은 제어된 전송 계층을 사용합니다.

이는 실제 Supabase 네트워크와 여러 기기의 브라우저 검증을 대체하지 않습니다. 프로젝트 연결 후 두 기기에서 확인해야 합니다. tests/browser.mjs는 별도 Chrome 프로필에서 화면과 연결 여부를 읽기 전용으로 확인하며, 공유 데이터를 변경하지 않습니다. 이 실행 환경에서는 Chrome 페이지 연결이 제한되어 시각 검증을 완료하지 못했습니다.

## 알림음 볼륨과 웹 푸시

웹 화면의 볼륨 슬라이더는 0~100%이며 기본값은 80%입니다. 0%는 무음입니다. 이전보다 큰 삼각파 알림을 6회 재생하며, 소리 테스트도 선택한 볼륨을 사용합니다. 소리 켜기/끄기와 볼륨은 각 브라우저에 저장됩니다. 다른 사용자의 설정에는 영향을 주지 않습니다. 기기 자체 볼륨과 브라우저 자동재생 정책은 별도로 적용됩니다.

푸시는 사이트를 닫은 기기에 서버가 보내는 알림입니다. 각 기기에서 **푸시 켜기**를 누르고 브라우저 알림을 허용합니다. 하단 **다음 보스 푸시 테스트 → 전송**을 누르면, 요청 시점의 최신 공동 시간과 서버 시각으로 가장 가까운 보스를 골라 **푸시를 켠 모든 기기에 같은 알림을 보냅니다**. 알림에는 `[테스트] Lv.레벨`과 다음 리젠 날짜·시간(한국시간)이 표시됩니다. 같은 시각이면 낮은 레벨 하나를 선택합니다. 리젠 시각까지 기다리지 않고 서버 큐에 요청하며 보통 1분 이내에 도착합니다. 여러 사용자가 눌러도 전체 테스트 전송은 서버에서 1분에 한 번으로 제한합니다. 푸시를 끈 기기는 받지 않습니다. 보스 시간이나 다른 사용자의 알림 설정은 바뀌지 않습니다. 푸시 끄기는 해당 기기의 서버 구독을 삭제합니다.

iPhone/iPad는 iOS/iPadOS 16.4 이상에서 Safari의 **공유 → 홈 화면에 추가** 후 웹앱을 실행해 푸시를 켭니다. PC와 Android는 지원 브라우저에서 알림을 허용합니다. 푸시 소리는 웹 볼륨 슬라이더와 별개로 운영체제의 알림 볼륨을 따릅니다. 전원 종료, 네트워크 끊김, 브라우저 강제 종료, 절전 또는 알림 차단 상태에서는 지연되거나 도착하지 않을 수 있습니다.

### 관리자의 최초 설정 — 모두 웹에서 진행

앱 설치 파일이나 명령줄 설치 도구는 사용하지 않습니다. 웹사이트를 배포한 다음, 화면의 **관리자용 최초 설정** 링크(push-setup.html)를 엽니다.

1. 페이지에서 알림 키를 만들고 복사하여 연결된 **Supabase Edge Function Secrets** 웹 화면에 저장합니다.
2. 발송기 코드를 복사하여 **Edge Functions → Deploy a new function → Via Editor**에 붙여넣고 **boss-push** 이름으로 배포합니다. 해당 함수의 **Verify JWT with legacy secret**을 끕니다. 함수 자체가 서버 발송 전용 키로 요청을 인증합니다.
3. 페이지의 예약 설정 SQL을 **SQL Editor → New query**에 붙여넣고 Run을 누릅니다.
4. **서버 연결 확인**을 누른 뒤 타이머를 새로고침하고 각 기기에서 푸시를 켜 테스트합니다.

Secrets 이름을 처음에 `1`, `2`, `3`으로 저장한 경우, 생성된 순서대로 `1=공개키`, `2=개인키`, `3=발송 인증 키`를 읽는 호환 처리가 있습니다. 같은 이름의 정식 `ECLIPSE_*` 항목이 있으면 정식 이름을 우선합니다. 값에 `ECLIPSE_이름=값` 한 줄 전체를 붙여넣은 경우 해당 접두어도 처리합니다. 이 복구는 기존 boss-push 함수 코드만 갱신하며 키를 새로 만들거나 기존 기기의 구독을 삭제하지 않습니다.

이미 서버를 설정했다면 새 웹 버전 배포 후 **관리자용 최초 설정 → 기존 푸시 서버 업데이트 → 업데이트 SQL 복사**를 사용해 SQL Editor에서 실행합니다. 기존 키·구독·보스 시간을 유지하며, 전체 전송 SQL이 적용되기 전에는 새 웹의 전송 버튼을 사용할 수 없습니다.

이 과정은 기존 보스 시간을 변경하지 않습니다. 생성한 비밀 값은 관리자 탭의 메모리에만 준비되며, 저장은 Supabase Secrets와 Vault에 합니다. 채팅·GitHub·공개 웹 소스에 붙여넣지 않습니다. 설정을 마칠 때까지 관리자 탭을 열어 두세요. 이미 알림 키가 등록된 서버는 새로운 키를 만들지 않으며, 발송기 코드와 기능 업데이트 SQL을 복사해 갱신할 수 있습니다.

정기 타이머 조회는 **1시간에 1회**입니다. 별도 서버 작업이 1분마다 현재 공동 보스 시간 6개를 확인하고, 보낼 알림이 있을 때만 Edge Function을 호출합니다. 브라우저가 닫혀 있어도 이 작업은 서버에서 실행됩니다. Supabase 프로젝트나 Cron이 중지되면 푸시도 중지됩니다.

발송 큐는 같은 리젠 회차의 중복 등록을 막고, 발송 전 공동 시간이 바뀌었으면 이전 큐를 취소합니다. 실패는 최대 3회 재시도하며 5분 넘게 지난 알림은 보내지 않습니다. 정상 발송의 목표는 1분 이내이나 OS 전달 지연이나 큰 대기열은 보장할 수 없습니다. 전송 결과를 받기 전에 연결이 끊기면 같은 알림이 재시도될 수 있으며, 기기 알림 태그는 같은 회차의 알림을 대체하도록 구성했습니다.

구독 주소와 기기 토큰 해시는 일반 방문자가 조회할 수 없습니다. 기기 토큰을 가진 해당 브라우저만 구독을 수정하거나 해제할 수 있고, 발송 큐 접근은 서버 전용입니다. 현재 구현의 등록 상한은 500기기입니다. 타이머 방문자는 로그인 없이 공동 시간을 편집할 수 있다는 기존 정책을 유지합니다.

서버 배포 권한이 없는 개발 환경에서는 코드 및 로컬 검증까지만 가능하며, **실제 푸시 활성화는 위 Supabase 웹 설정과 기기 수신 테스트 이후**입니다.

검증은 PostgreSQL에서 구독 권한, 중복 방지, 오래된 일정 취소, 실패 재시도와 해제를 실행합니다. 브라우저 API 대역으로 권한 거부, 등록 실패 정리, 구독 해제 후 재등록 방지와 서비스 워커 알림 동작을 확인하고, 실제 web-push 암호화 코드도 검사합니다. 이 검증은 실제 휴대폰/PC의 알림 수신 확인을 대체하지 않습니다.

관련 파일: dist/audio.js, dist/push.js, dist/sw.js, dist/manifest.webmanifest, dist/push-setup.html, supabase/push.sql, supabase/push-cron.sql, supabase/functions/boss-push/.
관리자 페이지의 복사용 자료는 **npm run build**가 서버 원본으로부터 생성합니다. GitHub Actions도 배포 전에 이 단계를 실행합니다.
